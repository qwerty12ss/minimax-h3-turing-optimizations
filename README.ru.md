# MiniMax H3: ускорения для Turing / RTX 2080 Ti

[English](README.md) | **Русский**

Исходники ускорений, тесты отдельных операций, параметры бенчмарков и численные результаты MiniMax H3 на **двух RTX 2080 Ti с увеличенной до 22 ГиБ памятью на каждой карте**. Тестовая система: **2 × Xeon E5-2686 v4, 128 ГБ RAM, PCIe 3.0 ×16 на каждой GPU и соединение NV2** между картами.

Это отдельная исследовательская публикация с новой Git-историей. В неё включены код, параметры, тесты, таблицы результатов и документация. Исходные изображения и видео, сгенерированные ролики, творческие промпты, переписка, веса моделей, сведения о развёртывании на сервере и готовые бинарные файлы исключены. Исторические замеры сохранены в численном виде; синтетические тесты позволяют отдельно проверять опубликованные операции.

## Что входит в репозиторий

| Компонент | Исходники | Назначение |
|---|---|---|
| Sol / SLA attention для SM75 | `src/h3_turing/attention/` | CUDA-маршрутизация, центроиды, INT8 attention и ограниченная асинхронная статистика маршрутов; сборка из исходников |
| Точные PDD scale/add и SUM | `pointwise.py`, `sum_reduce.py` | Сохранение исходных промежуточных округлений до FP16; SUM рассчитан на фиксированную геометрию тензоров |
| Общая подготовка QKV / FC1 | `shared/` | Разделение квантования CK с проверкой хеша исходника и передача ограниченных пакетов между двумя GPU |
| Нормализация, модуляция и RoPE | `norm_mod/`, `rope/` | Явные требования к арифметике и индексированию; исследовательские ядра для определённой геометрии |
| SwiGLU + ConvRot | `swiglu_convrot/` | Два результата: исходная FP16-активация и квантованный вход FC2; локальная FP32-таблица SiLU |
| Планирование VAE | `vae/` | Обратимое пространственное и временное распределение работы с сохранением существующего декодера и сборки результата |
| Экспериментальные варианты | `experimental/` | Слияние dequant/PDD, пороги по головам attention и ограничение диапазона квантования; ограничения описаны в заметках к тестам |

Включены готовые ComfyUI custom nodes, исходный TP2 core, интеграция PDD, установщик отдельного окружения и два переносимых workflow со звуком. **[Развёртывание с нуля на русском](docs/INSTALL.ru.md)**: оборудование, модели с SHA256, зависимости, настройки и запуск. Проверки свежего развёртывания описаны в [отчёте](docs/DEPLOYMENT_VALIDATION.md). Исторические личные материалы не нужны для новых тестовых workflow. Хеши исходников и адаптации приведены в [манифесте](results/source_manifest.json).

## Результаты полного выполнения задания

Все строки ниже относятся к нагрузке **960 × 512, 192 кадра, 24 кадра/с, 8 шагов** на **2 × RTX 2080 Ti**. Каждая строка — отдельный эксперимент с контрольными прогонами до и после кандидата, собственным seed и базовым вариантом. Холодные запуски исключены. Способы расчёта и проверки исходных данных описаны в [заметках к бенчмаркам](docs/BENCHMARKS.md) на английском языке.

| Эксперимент | Контроль, с | Оптимизированный вариант, с | Снижение времени |
|---|---:|---:|---:|
| Передача ограниченных пакетов общей подготовки QKV / FC1 | 168.05375 | 165.007 | 1.813% |
| Выбранный вариант временного планирования VAE | 165.307 | 163.619 | 1.021% |
| Совместная подготовка SwiGLU + ConvRot | 163.4205 | 159.739 | 2.253% |

Эти проценты **нельзя складывать**. В последней серии из девяти заданий прошли все 99 сравнений сырых дескрипторов для данного тестового случая. В более ранних сериях shared/VAE встречаются несколько групп контрольных отпечатков. Эти различия сохранены в результатах; универсальная побитовая повторяемость всего графа не заявляется.

## Сравнение с RTX 3090

Сохранённый исторический результат для RTX 3090 24 ГБ — **217.417 с на холодном запуске** при 960 × 512, 192 кадрах и 8 шагах. В нём использовался Sage `auto` вместе с memory-efficient Sage patch. Это **не замер чистого BF16 attention**. Конкретное ядро, выбранное режимом `auto`, не зафиксировано; сопоставимого прогретого запуска нет.

Профиль для 2080 Ti использует CK INT8 на шагах 1, 2, 7, 8 и разреженный Sol INT8 на шагах 3, 4, 5, 6. **Подтверждённого замера RTX 3090 с точно таким же гибридным профилем не найдено.** Поэтому историческая строка не используется для утверждений о превосходстве одной видеокарты над другой. Найденные публичные источники, отдельный замер Comfy Kitchen INT8 для другой нагрузки и ограничения сравнения собраны в [заметках по RTX 3090](docs/RTX3090.md) на английском языке и в [машиночитаемых данных](results/rtx3090.json).

## Запуск переносимых проверок

Для CPU-проверок нужен Python 3.10 или новее. GPU-зависимости устанавливаются отдельно. Импорт `h3_turing` не инициализирует CUDA.

```bash
python -m pip install -e ".[test]"
python -m pytest -q
python tools/summarize_results.py
```

Для нативных ядер нужны Linux x86_64, GPU с архитектурой SM75, CUDA Toolkit с поддержкой SM75, PyTorch и подходящее окружение ComfyUI / comfy-kitchen. Triton требуется для операций, написанных на Triton. Записанные версии ПО и оборудование приведены в [описании системы](docs/HARDWARE.md), а границы воспроизводимости — в [инструкциях](docs/REPRODUCIBILITY.md); оба документа на английском языке.

```bash
python tools/build_native.py attention swiglu
python benchmarks/attention_smoke.py
python benchmarks/verify_swiglu.py
H3_RUN_GPU_TESTS=1 python -m pytest -q -m gpu
```

Для `verify_swiglu.py` нужны две CUDA GPU и версия исходника CK с проверяемым хешем. Результаты локальной сборки и журналы проверок исключены из Git. Корректность GPU-вычислений и производительность необходимо заново проверять в целевом окружении; успешные CPU-тесты сами по себе этого не подтверждают.

Сведения об использованных сторонних исходниках и их лицензиях сохранены в [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) и каталоге `THIRD_PARTY_LICENSES/`.
