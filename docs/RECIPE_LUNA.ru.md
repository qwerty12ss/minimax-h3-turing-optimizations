# Дополнительный рецепт: Qwen TP2 + FC2 + кеш DiT

[English](RECIPE_LUNA.md) | **Русский**

**Этот вариант изменяет выход генерации.** При том же изображении, тексте, seed и настройках Qwen TP2 меняет численные результаты текстового кодирования. В результате отличаются **кадры и исходная звуковая волна**: это другой дубль. В проверенном примере менялись свет, пыль и положение объекта. Совпадение seed не означает совпадение видео. Ухудшение или улучшение художественного качества не установлено; выбирайте результат после просмотра и прослушивания.

Рецепт добавляет к нашему `preset=optimized` адаптации ускорений из [Luna-AI-Infra/ComfyUI-H3-2080Ti-TP, commit 945c326](https://github.com/Luna-AI-Infra/ComfyUI-H3-2080Ti-TP/tree/945c326132dc182d27299a44c003e6b8f5849ab6). Это измерение **нашего пайплайна с перенесёнными ускорениями**. Полный оригинальный репозиторий Luna в этом сравнении не запускался.

## Выбор режима

| `--luna-mode` | Что включено | Выход относительно исходного рецепта в проверенном тесте |
|---|---|---|
| `baseline` | Исходный `optimized`, без новых ускорений | Опорный дубль |
| `cache` | Повторное использование подготовленных CPU-паков DiT | Все сырые кадры, исходный звук и conditioning совпали побитово |
| `fc2` / `fc2_cache` | Измеренная политика FC2, отдельно / с кешем DiT | FC2 отдельно и кеш отдельно прошли побитовую проверку; их комбинация без Qwen отдельно не измерялась |
| `qwen` | Qwen TP2 с CPU-паками и двумя GPU-слотами | **Другие кадры и звук** |
| `qwen_fc2_cache` | Qwen TP2 + FC2 + кеш DiT | **Другие кадры и звук**; в тесте совпали побитово с режимом `qwen` |

Если нужно сохранить прежний дубль, выбирайте **`cache`**. Самый быстрый измеренный вариант — **`qwen_fc2_cache`**, с принятием изменившегося выхода. Это дополнительный режим; обычный запуск из [INSTALL.ru.md](INSTALL.ru.md) остаётся доступен.

Исходный энкодер **NVFP4 AWQ** сохраняется; конвертации в GGUF нет. Модель FL2VA INT8 ConvRot, отдельный PDD, SigmaShift 12/3, CFG 1, Euler, 8 шагов и профиль attention также сохраняются: CK INT8 на шагах 1, 2, 7, 8; Sol INT8 на 3–6. FC2 использует нашу геометрию шардов `[5376, 7168]`: только хвост `M=4650` получает плитку 12, основной `M=8192` остаётся на исходном ядре.

## Замер времени

Одна сцена и один seed, 960×512, 192 кадра, 24 fps, 8 секунд, 8 шагов; 2× RTX 2080 Ti по 22 ГиБ, NV2/P2P. Таймер — от ComfyUI `execution_start` до `execution_success`, включая Qwen, подготовку DiT, все шаги, VAE, звук и сохранение MP4. Очередь, запуск процесса и последующая диагностическая выгрузка исключены. В каждом задании генерация выполнялась заново.

| Режим | Полное время, с | Основание сравнения |
|---|---:|---|
| Исходный рецепт, два прогретых контроля | 167,856 и 174,832; медиана **171,344** | Свежие процессы без неиспользуемых экспериментальных паков |
| `cache`, прогретый кеш | **158,545** | −7,47% к медиане контролей |
| `qwen`, прогретые паки | **158,859** | −7,29% к медиане контролей |
| `qwen_fc2_cache`, оба кеша прогреты | **140,554** | **−17,97%** к медиане; −16,3…19,6% к двум контролям |
| `fc2` | **174,712** | −0,120 с / 0,07% к соседнему контролю 174,832 с; ощутимый выигрыш не подтверждён |

В показанном сравнительном видео были выбраны самые быстрые записанные полные прогоны: **167,317 → 140,554 с**, экономия **26,763 с / 16,0%**. Исходный 167,317 с был первым заданием в своей серии и исключён из приведённой выше оценки прогретых контролей. Эти два способа сравнения не смешиваются.

Первое создание кеша DiT: **185,169 с** целиком. Первое создание Qwen-паков при **уже прогретом DiT**: **159,670 с**. Полностью холодный запуск обоих кешей после исправления кеша отдельно не измерялся. Поэтому **140,554 с относится к повторному запуску в том же процессе**, а не к первому запуску после установки. Частоты не фиксировались, выборка мала; диапазон по двум контролям не является доверительным интервалом. Проценты отдельных ускорений не складываются.

## Установка и запуск

Нужны Linux x86_64, Python 3.12, CUDA Toolkit 13.0, две 2080 Ti **22 ГиБ**, двусторонний P2P и ориентировочно **128 ГБ RAM**. Дополнительные CPU-паки занимают **19,03 ГиБ DiT + 12,78 ГиБ Qwen = 31,81 ГиБ RAM** сверх остальных объектов и буферов. Это не кеш готового видео. Первая ошибочная реализация удерживала несколько поколений и привела к OOM; включён исправленный вариант с одним слотом на блок, удалением старого слота перед заменой и пределами 50 блоков / 22 ГиБ для DiT. Перед измерением выключенного режима нужен **свежий процесс**: аллокатор может удерживать закреплённую память после удаления Python-ссылок.

Выполните системную подготовку из [INSTALL.ru.md](INSTALL.ru.md), затем установите отдельный runtime. Команды ниже выполняются из корня этого репозитория:

```bash
export H3_RUNTIME="$HOME/h3-turing-luna-runtime"
export H3_LUNA_TRIAL_ROOT="$H3_RUNTIME/luna-output"

python3.12 tools/setup_stack.py --root "$H3_RUNTIME"
python3.12 tools/models.py download --root "$H3_RUNTIME"
mkdir -p "$H3_LUNA_TRIAL_ROOT"
ln -s "$PWD/recipes/luna" "$H3_RUNTIME/ComfyUI/custom_nodes/h3_luna_recipe"

# Проверка жизненного цикла кеша на CPU, без загрузки моделей.
"$H3_RUNTIME/.venv/bin/python" recipes/luna/test_cache_lifetime.py
```

Вместо `download` допустим проверяемый `models.py link` из базовой инструкции. Ссылку custom node создайте один раз; если её имя уже занято, проверьте существующий путь. Исходники должны оставаться на месте.

Для `qwen_fc2_cache`, `fc2` и `fc2_cache` соберите дополнительное ядро из исходников; режимам `cache` и `qwen` этот шаг не нужен:

```bash
git init "$H3_RUNTIME/cutlass"
git -C "$H3_RUNTIME/cutlass" remote add origin https://github.com/NVIDIA/cutlass.git
git -C "$H3_RUNTIME/cutlass" fetch --depth=1 origin afa1772203677c5118fcd82537a9c8fefbcc7008
git -C "$H3_RUNTIME/cutlass" checkout --detach FETCH_HEAD

"${CUDA_HOME:-/usr/local/cuda}/bin/nvcc" -arch=sm_75 -O3 -std=c++17 \
  --shared -Xcompiler=-fPIC -I"$H3_RUNTIME/cutlass/include" \
  recipes/luna/kernel.cu -o "$H3_LUNA_TRIAL_ROOT/libfc2_int8.so"
```

Запустите отдельный ComfyUI на свободном порту. В проведённом эксперименте весь процесс ограничивался 88 ГиБ RAM. Для Linux с работающим пользовательским systemd такой предел задаётся командой:

```bash
systemd-run --user --scope -p MemoryMax=88G -p MemorySwapMax=0 \
  python3.12 tools/launch.py --root "$H3_RUNTIME" --gpus 0,1 --port 8197 --cache-classic
```

`--gpus` задаёт физические индексы вашей пары; launcher проверяет SM75, память и P2P. `--cache-classic` сохраняет объекты загрузчиков и моделей для попаданий в CPU-кеш. Клиент ниже добавляет уникальную зависимость к каждому заданию, поэтому Qwen, все восемь шагов, VAE и сохранение выполняются заново. Используйте этот клиент для сравнения. Не отправляйте два задания одновременно. Предел 88 ГиБ не гарантирует наличие свободной памяти на всём хосте; остановите свой тест при её нехватке. Если systemd недоступен, нужен эквивалентный лимит памяти процесса/контейнера; эта команда не перенастраивает сервер.

В другом терминале из корня репозитория:

```bash
# Первый запуск создаёт паки; второй измеряет их повторное использование.
python3.12 tools/run_workflow.py workflows/h3_turing_8s_api.json \
  --url http://127.0.0.1:8197 --luna-mode qwen_fc2_cache
python3.12 tools/run_workflow.py workflows/h3_turing_8s_api.json \
  --url http://127.0.0.1:8197 --luna-mode qwen_fc2_cache
```

Для режима с сохранением прежнего выхода в обеих командах замените значение на `--luna-mode cache`. Для честного контроля остановите **этот** ComfyUI и запустите его заново с теми же параметрами, затем выполните два задания с `--luna-mode baseline`, первое считая прогревом. Простое переключение режима в процессе с готовыми экспериментальными паками недостаточно для сравнения памяти и времени.

Вывод содержит полное время, проверку конечности кадров/звука и численные `luna_recipe.stages`. При прогретом DiT ожидаются `pack_hits=50`, `pack_misses=0`, `retained_pack_bytes=20431001600`; при прогретом Qwen — `qwen_pack_hit=true`, `qwen_retained_pack_bytes=13722444800`. Для сохранения небольшого локального отчёта добавьте `--report /path/to/local-receipt.json`. MP4 находятся в `ComfyUI/output/video` выбранного runtime. Не публикуйте собственные ввод, вывод или отчёты без отдельной проверки.

Готовый публичный workflow использует синтетический рисунок и нейтральный текст. Он проверяет запуск; приведённое время получено на другом, непубликуемом входе и не обещается для синтетического рисунка. Для своего ввода следуйте базовой инструкции, сохраняя структуру узлов и проверенные 960×512 / 192 кадра. GUI-workflow дополнительного режима здесь не квалифицирован.

## Что проверено и что означает изменение выхода

В эксперименте кеш DiT и FC2 отдельно сравнивались по **всем 192 float32-кадрам до сжатия**, исходной звуковой волне, conditioning, token tags и опорному латенту: побитовых различий не найдено. Это проверка данного случая, а не гарантия для любых моделей и геометрий. Байты MP4 могут различаться из-за контейнера и метаданных.

Qwen изменил conditioning на относительную L2 **7,17×10⁻⁶**. Для всего float RGB-клипа PSNR к контролю — **24,09 дБ**, MAE — **0,02781** на шкале 0–1; относительная L2 исходного звука — **0,1151**. Эти величины измеряют **отличие**, а не художественное качество. Выборочные кадры не показали явного обвала детализации; полноценная субъективная оценка движения и звука не заявляется. Известный дефект исходной сцены около 6 с сохранился.

Измеренные вычислительные файлы `awq_tp.py`, `packed_shards.py` и `kernel.cu` перенесены без изменения байтов. Публичная обвязка удаляет диагностические выгрузки кадров/conditioning и возвращает только численные показатели. Её подключение и клиент проверены локально; **новый полный GPU-запуск именно опубликованной обвязки в этой правке не выполнялся**. Результаты проведённого эксперимента и границы переноса сохранены в [results/luna_recipe.json](../results/luna_recipe.json).

Исходники дополнительного рецепта и лицензии: [recipes/luna](../recipes/luna/README.md). Входные медиа, творческий промпт, сгенерированные ролики, переписка, веса, токены, адреса и пути исходного сервера в рецепт не включены.
